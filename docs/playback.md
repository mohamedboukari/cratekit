# Cratekit: playback

`crates/cratekit-audio/` plays the loaded track on the chosen output, the system default as fallback (SPEC, deck; ROADMAP #19, #20). `src-tauri/src/playback.rs` exposes it to the UI. Tested with `cargo nextest run -p cratekit-audio` (no audio device needed) and `-p cratekit`.

## Layout

| File | Contents |
| --- | --- |
| `crates/cratekit-audio/src/renderer.rs` | `Renderer::render` (the audio callback), `Command`, `Track`, `Shared` |
| `crates/cratekit-audio/src/filter.rs` | `DjFilter`: the deck's DJ filter (one knob, low-pass left, high-pass right) |
| `crates/cratekit-audio/src/engine.rs` | `Engine`: the output device, track preparation, commands, `Status` |
| `src-tauri/src/playback.rs` | `PlayerState`, the playback commands and the 30 Hz poller |

## How it fits together

```
playback_load ── decode_file + resample (blocking worker) ── Command::Load(Box<Track>) ──► rtrb ──► Renderer
play / pause / seek / set_filter / set_mode / stem gain, mute, solo ── Command ──────────► rtrb ──► Renderer
set_mode(stems) ── read the cached WAVs + resample ── Command::AttachStems(Box<StemSet>) ─► rtrb ──► Renderer
Renderer ── replaced track or stems (Retired) ──► rtrb ──► cleanup thread (frees it)
Renderer ── position, playing, ends, peak, rms ──► atomics ──► poller (33 ms) ──► playback_position, meter, playback_state
```

- **The audio callback** (`Renderer::render`) never allocates, frees, locks, blocks, does I/O or panics. Commands arrive over a lock-free `rtrb` queue; a replaced track leaves over a second queue and is freed on the cleanup thread (when that queue is full it waits in one of four slots; only if all are full is it leaked, counted in `Shared::leaked_tracks`, rather than freed on the audio thread). A test counts allocations on the rendering thread and asserts none.
- **Whole track in memory.** `Engine::prepare` takes the decoded track by value, makes it stereo (mono on both sides, the first two channels of anything wider), silences any non-finite sample from a damaged file, and resamples it to the device rate; `Engine::load` sends it ready to play. Seeking is then an index change. A loaded track takes about 21 MB per stereo minute; while preparing, the decoded input and the resampled output are both alive for a moment (about twice that).
- **Decks.** Commands and status carry a `DeckId` (only `A` in v0.1), so Performance mode (v0.2) can add a second deck without changing the engine's interface.
- **Latest load wins.** The app counts load requests: a load that finishes decoding after a newer one was asked for is dropped, and the counter is checked again under a lock right before the track is sent.
- **Click-free.** Play, pause, seek and load fade over 5 ms (`FADE_SECONDS`): pause fades out then holds the position; seek fades out, jumps, fades back in; a load fades the old track out and waits at the new one's start, stopped. A seek while paused moves at once. A seek or load during the last fade of a track is not counted as its end.
- **DJ filter (#56).** `playback_set_filter(value)`: -1 full low-pass, 0 off, 1 full high-pass (clamped). Inside the callback, `DjFilter` runs every frame before the meters, so the meters show what is heard. It is a 12 dB per octave state-variable filter in the topology-preserving form (Zavalishin, Simper), whose cutoff can move every sample without clicks; Butterworth Q, so no resonance peak and no clipping on loud tracks. Low-pass sweeps 20 kHz down to 80 Hz, high-pass 20 Hz up to 8 kHz, on an exponential curve. Within 2% of the centre (`DEAD_ZONE`) the output is the input exactly. The knob value follows a change with a 20 ms time constant (95% of the way after 60 ms), and the filtered signal blends in over the first 10% of travel, so crossing the centre from low-pass to high-pass never clicks. Filter state below 1e-20 is flushed to zero. The app keeps the knob value and every engine starts with it already set (`EngineOptions::filter`, no sweep after a device change); after waiting for a restart, a call sends the stored value, so the engine always ends on the newest one. The UI keeps one `playback_set_filter` call in flight during a drag and sends the newest value when it returns; a failure rolls the knob back to the last value Rust accepted. MIDI control comes with the controller targets (#38).
- **Stem mixer (#34).** A deck plays its track or its four stems (`PlaybackMode::Original` or `Stems`). In stems mode the app reads the track's cached stems (`stems::cache::read_folder`, the 16-bit WAVs the stems job wrote) and prepares them at the device rate (`prepare_stems`) **outside the load gate**, so play, pause and seek never wait for it (about 0.9 s for 5 minutes at 48 kHz); under the gate it then checks that the deck, the engine and the mode are unchanged and sends them (`Command::AttachStems`), and the renderer crossfades from the track to the stems' sum over 10 ms (`MIX_SECONDS`). A track that was not split, or whose stems cannot be read, keeps playing itself: stems never stop playback. `stems_set_gain(stem, gain)` (0 to 2, clamped), `stems_set_mute(stem, muted)` and `stems_set_solo(stem, soloed)` change one stem; while any stem is soloed, exactly the soloed ones are heard, muted or not. Every change ramps over 10 ms, so nothing clicks. At full gain the stems sum back to the track ("other" is the mix minus the rest), so switching modes is inaudible. Stems sent right after a load wait for that track, and a replaced track's stems leave with it to the cleanup thread (the mix then starts again from the track). The app keeps the mode across loads (what is heard follows the tab), but **every load starts with a neutral stem mix**, as the UI does; mode and settings survive an engine restart, after which the stems are prepared again for the new engine. The app records which track's stems the engine holds and forgets it on every load and engine change, so a reloaded track gets its stems again; a finished stems job marks the stems of a re-split track out of date and, in stems mode, attaches the new ones. Mode and stem calls send the stored value read under the gate, so the engine always ends on the newest one. `playback_set_mode("mastered")` plays the live mastering preview (#26, below); a mode switch that fails puts the previous mode back. Stems take about four times the track's memory while attached (about 92 MB per stereo minute at 48 kHz, 85 MB at 44.1 kHz), and about twice that for a moment while they are prepared.
- **Any device.** Any callback size and channel count: stereo goes to the first two outputs (extra outputs silent), a mono device gets the average. A partial frame at the end of a buffer stays silent.
- **Sample format.** The renderer works in `f32`. The engine uses the device's default format when it is `f32`, else an `f32` format the device also offers, else converts to its integer format (`i16`, `i32`, `u16`) at the output, through a scratch buffer allocated before the stream starts.
- **The cpal stream lives on its own thread** (on some systems it cannot move between threads). `Engine::close` stops it and waits for its threads even while other handles to the engine exist; dropping the last handle closes it too. The device's error callback sets `Status::device_error` only for errors that mean the output is gone (`is_fatal`: not an xrun, a refused real-time priority, a busy device, or the system rerouting the default output, which cpal follows by itself); see Unplugging below.
- **The engine starts on the first load,** on the output device and buffer size from the settings, so the app opens the audio device only when something is played. A chosen device that is not there falls back to the system default; a buffer size the device does not allow falls back to the device's own.
- **Changing device or buffer size while playing** (`audio_set_device`, or `settings_set` of `audioDeviceId` or `bufferSize`) restarts the engine, unless it already uses that device and buffer. The track is decoded first; then, holding the gate that play, pause, seek and loads also take, the old engine is closed (some systems give a device to one stream at a time), the new one opens, and the track is put back. Position and playing state carry over only for the track the engine really held; a newer track still loading starts at 0, stopped, as a normal load would. Play, pause and seek sent meanwhile wait and then act on the new engine. A track that can no longer be decoded leaves the deck empty and is not reloaded again. The setting is saved even when applying it fails; the UI then gets a notice instead of an error.
- **Unplugging:** when the output fails for real, the poller notices within 33 ms, reopens the system default, and playback resumes there once the track is prepared for it (about half a second); the UI gets `audio_device_changed {reason: "unplugged"}` and shows a notice. If no output can be opened, playback stops (`playback_state {playing: false, ended: false}`), the UI gets `reason: "lost"` with an error notice, and the device check keeps trying to bring the deck back. The stored choice stays, so when the chosen device comes back the engine moves back to it (`reason: "selected"`).
- **Device check (about every 2 s, even with nothing playing):** lists the device ids only (no device is opened or probed; a failed listing is skipped, never read as "no devices"), sends `reason: "list-changed"` when devices were plugged or unplugged so the UI reloads its list, follows a new system default when the app follows it (`reason: "default-changed"`), and moves back to the chosen device when it returns. Device ids that name an ALSA card by its number (`hw:CARD=0`) are left out: the number can change after a reboot, and the card's name-based id is kept.
- **Following the system default:** the setting `audioDeviceId` is null (the Settings picker's "System default" entry). Picking a device by name pins it.
- **Events:** about every 33 ms the poller reads `Engine::status` and sends `playback_position {sec}` while playing or after a seek, `meter {peakDb, rmsDb}` while there is sound (peak since the last read, floored at -96 dBFS), and `playback_state {playing: false, ended: true}` once when a track plays to its end (`ended` is false when a device change stopped or restarted the deck); the UI then loads and plays the next set list track, if the one that ended is in the set list and not last, unless the user picked another track or pressed a transport control meanwhile. The end count is compared with the previous status of the same engine only: a restarted engine (another device, a new buffer size) counts from zero again. There is no preload: between tracks there is a short silence while the next one decodes. The UI writes position and meters into refs and draws them on canvas (no React renders at 30 Hz).
- **Errors:** `no_audio_device` (no output), `audio_device` (the device failed or the engine stopped responding), plus the decoding and library codes for the track.

- **Mastered mode (#26).** `PlaybackMode::Mastered` is the B side of the Master tab's A/B, mastered in the audio callback in the export's order: the reference match when there is one (#27, 30 peaking filters, skipped without a reference), the preset's EQ and compressor (`PresetChain`), the makeup, the soft clipper (#144; on only when the preview's target is louder than -10 LUFS, `MasterPreview::clip`, as in the export; off, it only delays, so A and B stay aligned), the true-peak limiter, then the level match. The renderer builds the chain, the limiter and a delay ring when the engine starts, so nothing is allocated on the audio thread; `Command::SetMaster(MasterPreview)` carries plain values (the preset at its intensity with its reference curve, the makeup and a first guess of the level match, in dB); with the curve's 31 gains it is about 250 bytes, kept inline in the preallocated command queue rather than boxed, because the audio thread must not free a box.
  - **Alignment:** while a preview is on, what plays (track or stems) is delayed by the clipper's and the limiter's latency (27 samples, then 5 ms plus 11 samples) for the A side, so A and B stay sample-aligned through the 10 ms crossfade.
  - **No clicks:** the first preview while playing waits for a 5 ms fade out, like a seek, because what is heard shifts by that delay. After every reset (turning on, a seek, a load), the deck runs silently for that delay, so the fade in starts on real audio instead of the delay's silence. A preset or intensity change glides the filter coefficients over about 10 ms (16 steps of 32 frames; a blend of two stable biquads is stable). At the end of a track the delay plays out before the end counts.
  - **Loudness, measured live:** three matched meters (3 s) follow the chain's input, the chain's output and the limiter's output. The makeup is the preview's (the target minus the track's analysed LUFS, none when not analysed) plus what the chain takes off, so the B side drives the limiter as the export does. With level match on (the default, `SetLevelMatch`), the B side then follows the original's loudness, measured on the A side as heard (delayed like the B side, so right after a seek or a load the two meters line up and the match is not biased; before #144 the B side came back about 1.3 dB too loud for a moment); the preview's guess (minus the makeup) holds until the meters have heard audio. Gains ramp over 10 ms.
  - **On only on the B side:** at a silent point (a seek, a load, a pause) while the deck does not play mastered, the preview turns off (no CPU, no delay); switching sides without one keeps it, so A/B stays instant. The app keeps the preview with the track it was worked out for and re-sends it to a new engine or load only for that track in mastered mode; a preview for a track that is no longer the deck's is dropped.
  - **Cost:** about 0.25 µs per frame in release on an M4 Pro (1.2 % of a 512-frame callback), most of it the limiter's peak search; a reference match adds about 0.17 µs (the chain alone, frame by frame: 0.023 µs without it, 0.190 with it), about 2 % of the callback in all. `cratekit-core` and `cratekit-audio` are built optimized in development too (`[profile.dev.package]`), so `tauri dev` keeps the same headroom; the soft clipper adds about 0.04 µs while nothing clips (0.19 µs while it clips all the time), switched off a little less.

## Tests

- Renderer (synthetic tracks, no device): silence with nothing loaded; play fades in and then outputs the track exactly; pause fades out without a click and holds the position, play resumes there; seeking while playing fades out, jumps and fades in with no sample-to-sample step above a sine's own (no click), and lands where expected; seeking while paused moves at once, clamped to the end; the end stops playback and is counted once; a seek or load in the last 5 ms of a track keeps playing instead of ending; loading while playing fades out, waits at the new start and hands the old track back; any callback size (1 to 4096 frames) on mono, stereo and 6-channel devices; peak and RMS of a full-scale sine; **no allocation or free in `render`** through play, seek, pause and load.
- DJ filter (synthetic sines): within the dead zone the output equals the input exactly; full low-pass cuts 5 kHz by more than 24 dB and keeps 40 Hz; full high-pass cuts 60 Hz by more than 24 dB and keeps 15 kHz; turning further cuts more on both sides; jumping the knob from centre to full left, full right and back never steps more than 1.5 times a plain sine's own largest step; stable at 44.1 to 192 kHz; out-of-range values clamp and NaN is off; silence settles to exact zero; `jump` sets the knob with no sweep. Through the renderer: full high-pass removes a 440 Hz tone and the peak meter reads the filtered level; back at the centre the output equals the track sample for sample; a renderer created with the filter set is filtered from the end of its first fade in; `SetFilter` is part of the no-allocation test. UI: during a drag only one call is in flight and the last value is sent; a failure rolls back to the last accepted value.
- Engine: tracks are prepared as stereo at the device rate (mono doubled, extra channels dropped); NaN and infinite samples are silenced.
- App: position, meter and end events from status changes, dB conversion, which device to move to (the chosen one when available, else the default; none when already right), what a restart puts back (position and playing only for the track really on the deck), and the JSON the UI expects (`AudioDevice`, `AudioDeviceChanged` with every reason).
- Engine: which stream errors are fatal; which device ids are unstable.
- Mastered mode (renderer, synthetic tones at phases that are not whole periods): the mastered mode plays the track until a preview is set; turning on while playing fades out and back in without a click; with a neutral preview A and B are equal sample for sample; the B side stays under the ceiling with +12 dB of makeup; level match keeps A and B within 1 dB (and without it the makeup is heard), also with Club at 0.6 compressing hard, where the live meters add back the compressor's loss; switching sides, seeks and loads (on either side) and preset changes do not click; the last milliseconds play out and the end counts once; the preview stops at a silent point while B is not heard; a new track has no tail of the old one; render never allocates with all of it; a reference curve lifts a 10 kHz tone 4 dB against a 200 Hz one on the B side (the makeup takes back the level, as the export's loudness targeting does) and changes nothing at intensity 0; preset glides and the no-allocation test include a reference; right after a seek a neutral B side plays within 0.3 dB of A (the level match compares A as heard with B's output); a neutral preview stays sample-aligned with the clipper on and off.
- Checked by hand on macOS: the default output opens (48 kHz), the position advances in real time, a seek lands, the end is reported; the devices are listed with the default marked; a missing device id falls back to the default; a 256-frame buffer plays.
