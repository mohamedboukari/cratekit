# Changelog

All notable changes to Cratekit are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- Multi-language UI (#80): i18next with typed keys, every UI string in per-area translation files, a French translation, Settings, General, Language (English by default for every user, never taken from the system), Rust errors translated by code, every native menu item and the Settings window title in the chosen language (`app_set_menu_labels`), export changes and the CPU reason sent as data or codes instead of English text, and background jobs named from their kind and stage (`job_progress` gains `stage`). Dependencies: `i18next` 27.1.1 and `react-i18next` 18.0.1 (MIT).
- ROADMAP: test DJ wishlist and multi-language plans linked to their issues: v0.2 sampler, slip and reverse, beat jump, 16 hot cues, pitch range (#75 to #79); i18n foundation with French (#80, Phase 1); Arabic right-to-left (#81, Phase 3); more languages and 13 later ideas (#82 to #95).
- `stratum-dsp` behind the tempo and key detector traits, completing #10: `StratumTempo` and `StratumKey` in `analysis::stratum`, behind the `stratum` cargo feature (off by default). On the synthetic test loops our own detectors were more accurate and about 5 times faster, so they stay the default (comparison in `docs/analysis.md`). Clippy runs on both the default and the all-features build; the Rust tests and coverage run with all features.
- Tempo and key detection in `cratekit-core`, part 1 of #10: `TempoDetector` and `KeyDetector` traits with our own detectors, `OnsetTempo` (onset envelope, autocorrelation that keeps slow grooves with off-beat hi-hats at their real tempo, beat-grid refinement, folded into 70 to 180 BPM, no estimate for steady tones) and `ProfileKey` (note-filter chroma matched to Krumhansl-Kessler profiles). Meets the SPEC targets on the synthetic loops (BPM within 0.5, correct key) and analyzes 90 s in about 0.35 s in release. `synth::hats` adds noise-burst percussion for tests.
- Synthetic test audio in `cratekit-core` (#9): `synth` module (tests and the `test-helpers` feature only) with a sine at a level, a kick on every beat, chords (changing on bar lines) and off-beat bass in a key, and the SPEC acceptance loop, plus level and single-frequency measurement helpers; doc tests now run with all features.
- Camelot wheel in `cratekit-core` (#11): `Key`, `PitchClass`, `Mode` and `Camelot` types; key to Camelot mapping and back for all 24 keys (checked against the SPEC table); `matches()` (same code, ±1 on the wheel, relative major or minor) and `mixes_well_with()` (the three partners, in the order the UI shows them); module doc in `docs/analysis.md`; parsing `"8A"` with typed errors; scale flags for the chroma display.
- Project docs: product spec, architecture, roadmap, UI design system and clickable mockup.
- Dev tooling for Claude Code: project skills (`ship`, `realtime-audio`, `license-check`, graphify), permissions allowlist, no-em-dash hook, context7 MCP, rust-analyzer and TypeScript LSP plugins (Vercel plugins disabled for this project), graphify knowledge graph with git hooks.
- `CHANGELOG.md`, PR template, `.gitignore` that keeps test audio and VirtualDJ files out of git.

- Cargo workspace (`cratekit-core`, `cratekit-audio`, `src-tauri`) on Rust 1.100, edition 2024, with workspace lints (no unwrap/expect, no println!, no unsafe, `#[expect]` over `#[allow]`).
- Runnable Tauri 2 app shell (`io.github.mohamedboukari.cratekit`, native titlebar, 1280x800, min 1024x640, strict CSP) with a first IPC command (`app_version`).
- React 19 + TypeScript 7 + Vite 8 UI with Tailwind v4, shadcn/ui (Base UI), bundled Space Grotesk and JetBrains Mono fonts, Vitest.
- Tooling: cargo-nextest, cargo-deny, cargo-shear, cargo-llvm-cov, taplo, typos, bacon; oxlint (type-aware), Prettier, knip; husky + lint-staged + commitlint; GitHub Actions CI across six targets.
- README (developer setup) and MIT LICENSE.
- Open source release: SECURITY.md (private vulnerability reporting), CONTRIBUTING.md, CODE_OF_CONDUCT.md (Contributor Covenant 2.1), issue templates, Dependabot (cargo, bun, GitHub Actions), CodeQL (Rust, TypeScript), gitleaks, zizmor and dependency review workflows; CI runs all six targets on every pull request.
- Doc tests in the gates; pre-push skips delete-only pushes.
- GitHub issues and milestones for every ROADMAP task; each ROADMAP line links to its issue.
- Settings, dialogs and first run (#1, closes the redesign): native app menu with Settings... (Cmd/Ctrl+,) opening a separate Settings window (audio output, library folders, processing backend, models, controller, keyboard), shown in the page in the browser demo; file and folder pickers (`tauri-plugin-dialog`, MIT OR Apache-2.0); empty library drop zone with Add tracks and Add folder; drop files anywhere on the window (macOS and Linux; off on Windows, where it would break the set list's drag and drop); VirtualDJ export dry-run dialog; model download dialog with checksum step; hot cue rename, recolour and delete; live job progress on track rows. New IPC: `open_settings_window`, `hotcue_update`, `settings_changed` event, file drop event. `docs/UI.md` rewritten around the real app; the HTML mockup (`docs/ui-preview.html`) is removed in favour of the live demo.
- Tool tabs (#1; UI side of #18, #28, #35, #40): Analyze (key, chroma with the key's scale from Rust, mixes-well-with chips that filter the browser, tempo, drop and mix-out jumps, loudness, re-analyze); Master (presets with Rust's default targets, intensity, loudness target, reference track from the context menu, level-matched A/B, output meters drawn from the meter ref, WAV export); Stems (model download, split with progress and cancel, 4 or 2 stem mixer with mute, solo and volume, per-stem waveforms, export); Controller (device drawing that lights up from control events, MIDI mapping table with learn, cancel and moved-binding notice; keyboard shortcut list without a controller). What you hear follows the tab. New IPC: `master_presets`, `playback_set_level_match`, `stems_info`, `stems_set_solo`, `stems_export`; `master_export` writes to the output folder; `midi_learned` reports `replaced`; `midi_mappings` lists every target; `job_progress` carries `trackIds`; controller mute, A/B and pad-page presses drive the UI state.
- Deck and browser (#1, #55, #56): canvas waveform with beat-phrase grid, draggable hot cue flags and overview; transport with 8 paged hot cue pads, CUE and a DJ filter knob; virtualized, sortable track browser (TanStack Table v9 + Virtual) with keyboard selection and sorting, filter chips (key match and near-BPM, both decided in Rust), search, a row context menu and a narrow column layout for small windows; set builder side list with Rust-computed key and BPM fit; device card and job queue in the sidebar and status bar.
- Product direction: v0.1 prep tool, then a v0.2 Performance mode toward replacing VirtualDJ (SPEC Vision and Module 8, ROADMAP v0.2, issues #57 to #66). Set builder side list (#55) and a deck filter knob (#56) added to v0.1 after test DJ feedback.
- UI foundation for the redesign (#1): typed `CratekitApi` with a Tauri implementation and a fake-data mock (never in production builds), Zustand stores, laptop-first resizable shell (sidebar, deck, track browser, tool panel, status bar), keyboard shortcut map, toasts, and a GitHub Pages demo in mock mode.

### Changed

- UI stack: React 19 + Vite + TypeScript with bun and Vitest (the first draft said Svelte 5 with pnpm).
- Database notes: SQLite through rusqlite in WAL mode with a single writer connection.
- Platforms: macOS universal (arm64 + x86_64), Windows x86_64 + ARM64, Linux x86_64 + arm64, all tested in CI. Stems use the GPU when available (CoreML / DirectML) with CPU fallback.
- Hot cues: 8 per track (pads page 1 to 4 / 5 to 8). New Settings module (audio output device, folders, processing backend).
