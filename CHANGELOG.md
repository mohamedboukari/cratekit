# Changelog

All notable changes to Cratekit are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- Generated IPC types (#16): every Rust payload struct and enum derives `ts_rs::TS` behind a new `ts` cargo feature (on in test runs, never in the app), and the Rust tests write the TypeScript types to `ui/src/lib/bindings/`. A type-level test (`ui/src/lib/bindings.test.ts`) makes `tsc` prove the UI's `types.ts` agrees with them in the direction the data flows, and CI fails when the committed bindings are stale. Job payloads now use Rust enums (`JobKind`, `JobStage`) instead of strings; the JSON sent is unchanged. Dependency: `ts-rs` 12 (MIT), test builds only.
- Save the set list as a crate (#55): the app answers `crate_create` (with the set's tracks, in one step, so a failed save leaves no empty crate), `crate_add_tracks` and `crate_remove_tracks`. A saved set keeps its order: a crate lists its tracks in the order they were added, not by library order. Adding again appends, a track already in the crate keeps its place, and a track no longer in the library is skipped. An empty crate name is refused (new error code `invalid_name`). With the set list transitions in Rust (#21), the set builder now runs on real data.
- DJ filter (#56): the deck's filter knob now changes the sound. `cratekit-audio` has a 12 dB per octave state-variable filter (`DjFilter`) in the audio callback: low-pass to the left (20 kHz down to 80 Hz), high-pass to the right (20 Hz up to 8 kHz), the untouched signal within 2% of the centre, smoothed (20 ms time constant) and blended in near the centre so turning it never clicks. The app answers `playback_set_filter` and keeps the value across a device change (a new engine starts with it set). During a drag the UI keeps one call in flight and sends the newest value; the knob text says "Off" exactly where the sound is untouched (below 2%). Keyboard control works on the focused knob (arrows, Shift for bigger steps, Home, End, Delete or double-click to reset); MIDI comes with the controller targets (#38).
- Analyze tab on real data (#18): the tab shows the key and Camelot code, the 12 chroma bars with the scale notes marked, the mixes-well-with chips, tempo, first beat, energy and loudness from the stored analysis; the chips use the Camelot matching in `cratekit-core` and filter the library in Rust (`matchCamelot`). Checked on real tracks. Drop and mix-out stay empty until auto cues (#48).
- Waveform (#13): the analysis computes min, max and RMS columns of the whole track (20 per second, one byte each, about 22 KB for six minutes), stores them with the analysis, and `track_detail` returns an overview of up to 1200 columns that the deck draws. `ANALYZER_VERSION` is now 2, so tracks analyzed before count as needing analysis and get their waveform when analyzed again.
- Output device choice and hot-plug fallback (#20): the app lists the output devices (`audio_list_devices`) and plays on the one chosen in Settings (`audio_set_device`, saved as the `audioDeviceId` setting; a "System default" entry follows the system default), with the saved buffer size when the device allows it. Changing the device or the buffer size while playing restarts the engine and keeps the track, position and playing state; play, pause and seek sent meanwhile wait for it. When the output fails for real (not on an xrun or a system reroute), the failure is detected within 33 ms and playback resumes on the system default once the track is prepared for it (about half a second), with a notice; if no output opens, a "no audio output" notice, and the deck comes back when a device returns. The chosen device is used again when it comes back, a new system default is followed, and the device list is checked about every 2 s (ids only) so the UI list stays current. Numbered ALSA card ids are not stored. `audio_set_buffer_size` is gone from the IPC contract: the buffer size is the `bufferSize` setting.
- Settings saved for real (#21): `cratekit_core::settings::Settings` holds every setting the Settings window shows, with Rust-side defaults and rules; the library stores one JSON value per key, so settings survive restarts, and a value from another version that no longer loads keeps its default instead of breaking the rest. The app answers `settings_get` and `settings_set` (checked: an unknown key, a wrong type or a buffer size other than 128, 256, 512 or 1024 is `invalid_setting`) and sends `settings_changed` to every window. The buffer size is now saved through settings (applying it to the audio output comes with #20). The settings load error at startup is gone; the master presets error at startup remains until mastering exists. Set list transitions move to Rust (`setlist_transitions`: same key or a Camelot partner, BPM change in percent, more than 6% is a jump; part of #55), so a saved set list shows its fit. Not done yet: choosing the output device (#20) and watching folders for new files (SPEC Module 1, no task yet).
- Playback (#19): `cratekit-audio` plays the loaded track on the default output with cpal. The audio callback (`Renderer::render`) never allocates, frees, locks or blocks (a test proves it): commands arrive over an `rtrb` queue, replaced tracks are freed on a cleanup thread, position and meters go out through atomics. Play, pause, seek and load fade over 5 ms so nothing clicks. The app answers `playback_load`, `playback_play`, `playback_pause` and `playback_seek` and sends `playback_position`, `meter` and `playback_state` (end of track) about 30 times a second; the engine starts on the first load. New UI error codes `no_audio_device` and `audio_device`. CI installs ALSA headers on Linux. Dependencies: `cpal` 0.18 (Apache-2.0), `rtrb` 0.4 (MIT OR Apache-2.0).
- Background analysis (#15): `analysis::track::analyze_file` decodes a track and measures loudness and energy on all of it and tempo, first beat and key on its middle 90 s, with progress (`progress::ProgressSink`) and cancellation (`progress::CancellationToken`, also inside decoding); the tempo detector now reports the first beat. The library stores results (`store_analysis`, schema 2 adds the chroma) and `track_detail` returns them. The app runs analysis jobs on a worker thread with `analyze_tracks`, `job_cancel` and `jobs_set_paused` and the `job_progress` (now with `queued`, sent as soon as a job is queued), `job_done` and `job_failed` events; a job skips tracks that fail (a panic included) and reports how many. Progress moves during decoding and loudness, and cancel works inside them; the onset envelopes no longer copy the track. A 6 minute track analyzes in about 1 s (release). The UI shows "--" for values a track does not have (no beat, no key, silence), shows queued jobs, refreshes after a cancelled or failed analysis, prints job progress as a percentage, and the "First beat" label replaces "First downbeat".
- Track library in `cratekit-core` (#14): `library::Library` on SQLite (rusqlite with SQLite built in, WAL, foreign keys, one writer) with the schema as numbered migrations; adding files and whole folders (subfolders searched, hidden files skipped, files already in the library skipped) with tags and properties read by `audio::probe_file` (ID3, MP4, Vorbis comments) on several threads and a cheap file fingerprint; filtered listing (crate, search, BPM range, near BPM within 3, key match, has stems), sidebar counts, track detail with cues, and removal that never touches the files. 500 tracks are added and listed in well under the SPEC's 5 s. Tags with several values keep them all. The app opens `cratekit.db` in its data folder and answers `library_add_paths` (files read without holding the library; the first failure is reported when nothing could be added), `library_list`, `library_counts`, `track_detail` and `crates_list`; new UI error codes `database` and `database_too_new`. Apple Lossless (ALAC) in M4A now decodes too. Dependencies: `rusqlite` 0.43 (MIT), symphonia's `alac` feature (MPL-2.0).
- Audio decoding and resampling in `cratekit-core` (#8): `audio::decode_file` reads MP3, WAV, FLAC, AIFF, M4A (AAC) and Ogg Vorbis to a planar `f32` `AudioBuffer` (format found from the content; MP3 and Ogg encoder delay trimmed where the file records it, M4A priming kept for now; a damaged packet becomes silence so later audio keeps its timeline position), and `audio::resample` changes the sample rate with rubato's FFT resampler, aligned sample for sample. New `CoreError` variants (including `ReadFile` with the path) and UI error codes (`unsupported_format`, `decode`, `no_audio`, `audio_processing`). Tested on synthetic tone files made with ffmpeg (`tests/fixtures/`). Dependencies: `symphonia` 0.6 (MPL-2.0), `rubato` 5 (MIT OR Apache-2.0).
- Loudness and energy in `cratekit-core` (#12): `measure_loudness` (integrated LUFS with BS.1770 gating and true peak in dBTP, through the `ebur128` crate, MIT) and `energy_score` (1 to 10 from loudness, onset density and brightness; a heuristic to re-tune on real tracks in #22). Checked with synthetic tones modelled on EBU Tech 3341; 90 s of stereo takes about 0.1 s in release. Dependency: `ebur128` 0.1.
- Multi-language UI (#80): i18next with typed keys, every UI string in per-area translation files, a French translation, Settings, General, Language (English by default for every user, never taken from the system), Rust errors translated by code, every native menu item and the Settings window title in the chosen language (`app_set_menu_labels`), export changes and the CPU reason sent as data or codes instead of English text, and background jobs named from their kind and stage (`job_progress` gains `stage`). Dependencies: `i18next` 27.1.1 and `react-i18next` 18.0.1 (MIT).
- ROADMAP: test DJ wishlist and multi-language plans linked to their issues: v0.2 sampler, slip and reverse, beat jump, 16 hot cues, pitch range (#75 to #79); i18n foundation with French (#80, Phase 1); Arabic right-to-left (#81, Phase 3); more languages and 13 later ideas (#82 to #95).
- `stratum-dsp` behind the tempo and key detector traits, completing #10: `StratumTempo` and `StratumKey` in `analysis::stratum`, behind the `stratum` cargo feature (off by default). On the synthetic test loops our own detectors were more accurate and about 5 times faster, so they stay the default (comparison in `docs/analysis.md`). Clippy runs on both the default and the all-features build; the Rust tests and coverage run with all features.
- Tempo and key detection in `cratekit-core`, part 1 of #10: `TempoDetector` and `KeyDetector` traits with our own detectors, `OnsetTempo` (onset envelope, autocorrelation that keeps slow grooves with off-beat hi-hats at their real tempo, beat-grid refinement, folded into 70 to 180 BPM, no estimate for steady tones) and `ProfileKey` (note-filter chroma matched to Krumhansl-Kessler profiles). Meets the SPEC targets on the synthetic loops (BPM within 0.5, correct key) and analyzes 90 s in about 0.35 s in release. `synth::hats` adds noise-burst percussion for tests.
- Synthetic test audio in `cratekit-core` (#9): `synth` module (tests and the `test-helpers` feature only) with a sine at a level, a kick on every beat, chords (changing on bar lines) and off-beat bass in a key, and the SPEC acceptance loop, plus level and single-frequency measurement helpers; doc tests now run with all features.

### Changed

- Phase 2 order (#5): stems first, then mastering. Stems are everyday prep work for most DJs and carry the most platform risk (an ML runtime per target); mastering mainly serves the DJ's own edits and recorded mixes. The ROADMAP lists the stems tasks first, with the ONNX Runtime research (#29, #114, #115) ahead of the model download.
- Minimum OS versions (#7): macOS 14.2, Windows 10 22H2 or 11 (ARM64: 11), Ubuntu 22.04 or Debian 12, with the reasons and a per-target table of native dependencies in `docs/ARCHITECTURE.md` and the SPEC Non-functional table. The macOS bundle sets `minimumSystemVersion` to 14.2, because cpal links Core Audio functions that exist only from 14.2 and an older macOS would otherwise crash at launch. Linux release builds must run on Ubuntu 22.04 so the AppImage runs there. Known stems gaps (no ONNX Runtime for Intel Macs, AVX2 and glibc 2.39 in the prebuilt `ort` binaries) are recorded for #114 and #115; follow-ups: CI installer builds (#113), launch smoke tests (#116), the retiring Intel macOS runner (#117) and the cpal symbols (#118).
- Tempo detection on real tracks (part of #22): soft beats with a clear grid (orchestral, light acoustic) now get a tempo. The "no beat" floor is 0.10 instead of 0.15; beats from 0.10 to 0.15 also need a confidence of 0.75, and short clips need more, so steady tones (including sub-bass at 48 kHz), crackle, rain and speech-like sounds give no tempo. On 10 Creative Commons tracks with publisher BPM tags: 6 exact (5 before), 1 octave, 1 tag that looks wrong, 2 misses investigated and recorded in `docs/analysis.md`.
- CI: the Linux system packages step kills each attempt after 4 minutes and retries up to 3 times, switching from the runner's regional Ubuntu mirror to the main one; the slow mirror had hung the job until the time limit.
- UI stack: React 19 + Vite + TypeScript with bun and Vitest (the first draft said Svelte 5 with pnpm).
- Database notes: SQLite through rusqlite in WAL mode with a single writer connection.
- Platforms: macOS universal (arm64 + x86_64), Windows x86_64 + ARM64, Linux x86_64 + arm64, all tested in CI. Stems use the GPU when available (CoreML / DirectML) with CPU fallback.
- Hot cues: 8 per track (pads page 1 to 4 / 5 to 8). New Settings module (audio output device, folders, processing backend).
